Cluster Builder

Three empty mini PCs, a network cable each, and this page. When it says Done three times, you have a Proxmox cluster with a Home Assistant VM that restarts on another machine if one dies.

1 Tell it about your house

The root password is what you will type once into Cluster Guard later, and into any node's web page (https://<node address>:8006). It is stored here only as a hash.

How the machines get the installer

The three nodes

NameAddressPrivate link address

Give each node a free address on your network, outside the router's DHCP range, and set the second network port of every box on its own little switch for the private link (the link addresses can stay as they are).

The Home Assistant VM

With the move ticked, Build first takes a full backup of this Home Assistant (everything but this add-on). When the new VM boots its Welcome screen, the add-on restores that backup into it, and step 5 tells you when to shut this machine down. Without it, the new Home Assistant shows its Welcome screen for a manual restore.

The MAC address is made up here for the new Home Assistant VM. It is not from one of the new machines and not from this Home Assistant (this machine): there is nothing to look up. Give it a DHCP reservation in your router now, so the new Home Assistant comes up at an address you know. It cannot share this machine's address while both are running; once the move is done and this machine is off, you can give the VM's MAC the old address if you want to keep it. Home Assistant OS will boot on the first node, download its core, and show its Welcome screen.

2 Build the installer

Downloads the Proxmox installer and the Home Assistant OS image (about 2 GB) and makes one installer image that works for all three machines. Needs internet and free.

    
  
    

  
    
    
    3 Point the machines at this add-on
    
    
    
    
    
    
      
      
    1. Router: nothing to change. The add-on answers the machines' network-boot requests itself, next to your
        router's normal DHCP. Only if your router already has a network-boot (PXE) setting pointing somewhere else, clear it
        or set it to server , file ipxe.efi.
      2. 
      
    2. Each box, once. Start it with a keyboard and screen, enter the firmware setup (Del or F2 on most mini
        PCs), turn Secure Boot off (the network boot loader is not signed), enable network boot (PXE, IPv4) and put it
        before the disk. From then on it never needs a stick. The box needs 4 GB of memory or more: the installer
        runs from memory.
      3. 
      
    3. Turn the boxes on. Each one appears under step 4 as it asks to boot; say which node it is. It installs
        itself, restarts, and finishes alone. Any machine you do not assign is told to start from its own disk, so
        nothing else on your network can be wiped.
      4.

    4 Watch the machines install
    
    
    
      
    Cable each box to your house network, plug in the stick, power it on. If it does not boot from the stick, press the
        boot-menu key as it starts (F7 on MeLE, F11 or F12 on most others) and pick the stick. The stick erases the
        machine it boots on, so only plug it into the new machines.
    
      
    Each machine installs itself, turns itself off, and waits for you to remove the stick and turn it back on.
        Then it finishes on its own. The first box you boot becomes the first node; do the others whenever you like, together
        or one at a time.
    
    
    
    
    
      
    Machines that ask to boot from the network show up here. Say which node each one is and it gets the installer at
        its next try (within 15 seconds). The first one to install becomes the first node and gets the Home Assistant VM.
    
      
    
    
    
    
    
    
    
      
      Forget all machines and progress? The nodes themselves are not touched, only this page's memory of them.

        both talk to your devices, then open . Add the Cluster Guard integration there with a node's
        address and the root password, once.
